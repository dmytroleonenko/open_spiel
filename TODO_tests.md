# Test Case Verification Checklist

This checklist tracks the verification of JavaScript board states (`XYZState` rendered in `TESTS.html`) against their corresponding C++ test definitions (e.g., in `long_narde_test_*.cc` files).

**Important Notes for Verification (Learnings from `long_narde_test_endgame.cc`):**

*   **Raw State Strings (`<pre id="...-raw">`):** Direct comparison of JS state via `<pre>` tags containing raw state strings might be difficult or impossible. These tags were not consistently found for `endgame` tests using the `-raw` suffix convention. It's recommended to assume they might be missing or differently formatted.
*   **Focus on Textual Descriptions:** Prioritize verifying the textual descriptions within the corresponding `<div class="test-case" id="test-...">` block in `TESTS.html` (Objective, Board Setup, Dice Roll, Scores, Expectations) against the C++ code located using the `//StartTest:` anchor in the relevant `.cc` file.
*   **Minor Discrepancies:** Be aware that minor inconsistencies might exist between the C++ setup and the HTML description (e.g., exact score values, minor setup details). Focus on the core logic, board positions, dice, player, and objective/expectations alignment. Correct significant descriptive errors in `TESTS.html` if found.
*   **Editing Files:** If edits to `TESTS.html` or this `TODO_tests.md` file are needed and the standard edit tool fails, try using the `mcp_UltimateEditor_tool_replace_block` tool, providing the absolute file path (e.g., `/Users/dleonenko/open_spiel/TESTS.html`).

**Verification Steps for Each Test:**

1.  Identify the C++ test function corresponding to the `XYZ-raw` definition in `TESTS.html` (using the comment like `/* Corresponds to test-... */` and searching for the `//StartTest: ...` anchor in the `.cc` file).
2.  Compare the parsed `XYZState` JavaScript object (derived from the `<pre id="XYZ-raw">` tag in `TESTS.html`) with the board state defined in the C++ test setup (e.g., using `SetupGameAndStates`). *If the raw state string cannot be found, rely on step 7.*
3.  Verify checker counts in the `XYZState`: Ensure White has 15 checkers and Black has 15 checkers *unless* bearing off has occurred according to the C++ test logic.
4.  If `<15` checkers for White in `XYZState`: Verify all White checkers are on points 0-5 (White's home board).
5.  If `<15` checkers for Black in `XYZState`: Verify all Black checkers are on points 12-17 (Black's home board).
6.  If total checkers `<30` in `XYZState`: Verify the score representation is correct based on the number of borne-off checkers defined or implied by the C++ test setup.
7.  Verify Test Description: Check the HTML content/comments near the `<pre id="XYZ-raw">` tag and ensure the description accurately reflects the board state and the purpose of the corresponding C++ test.
